# AGENTS.md

Instructions for every coding agent working in this repo (Claude Code, Codex, Cursor, anything else).
Read this file and `SPEC.md` before writing any code.

## What we're building

**Mandate** — attenuated delegation chains for AI agents, enforced at the resource boundary, with Ethereum-backed revocation. Built from scratch at ETHGlobal Mumbai 2026. `SPEC.md` is the source of truth for behaviour, formats and security rules.

## Who owns what — stay in your lane

Two people build in parallel, each with their own agent, on their own branch. **An agent only edits files its owner owns.** If you need something from the other side, code against the interface in your prompt, stub it so it **always denies**, and tell your human.

## Branches and merging

- `main` holds only merged, working code.
- Karan pushes the scaffold + `types.ts` + `config.ts` **directly to `main` first**, then both work on their branches.
- Havinash pulls that into his branch with `git merge origin/main`.
- Merge order at integration time (~18:30): **Havinash's PR → `main` first**, then Karan merges `main` into `karan/mvp`, wires the verifier into the payment service, and opens his PR.
- Never push directly to the other person's branch.

## Commits

- **Commit every 20–30 minutes of work**, or sooner when a coherent piece is done and its tests pass. Never let more than 30 minutes of changes pile up.
- **Push after every commit.**
- One concern per commit. Small diffs.
- Messages: short, lowercase, plain English, the way a developer writes them at a hackathon.
  - Good: `add narrows check with unit tests` · `fix nonce race in execute` · `deploy registry to sepolia` · `wire verifier into payment service`
  - Bad: `feat(core): implement comprehensive narrowing validation logic` · anything with emojis or bullet lists
- **No trailers.** No `Co-Authored-By`, no `Generated with …`, no tool or model names in the message.
- Use the git identity already configured on the machine. Never change `git config`.
- Never rewrite history: no `--amend` on pushed commits, no rebase of pushed commits, no force-push, no editing commit dates.

## Security rules (non-negotiable)

1. The `/execute` endpoint is the product. Client-side checks are never security.
2. **Fail closed.** Any error, missing env var, RPC failure or unexpected value = deny. Stubs must deny, never allow.
3. EIP-712 domain `chainId` and `verifyingContract` come from config, never from a token.
4. Equality is valid attenuation: use `>` not `>=`.
5. Amounts are `bigint`; over HTTP they're decimal strings.
6. No pre-existing project code. Public libraries are fine.
7. Never commit secrets. `.env` is gitignored. Look up external addresses in official docs, never from memory.
